# Lesson01：Webの仕組みとAPI入門

## はじめに

これまでの学習では、Reactを使って画面を作成してきました。しかし、実際のWebアプリケーションではデータを外部から取得して表示するのが一般的です。

このChapterでは、**Web APIとは何か、どのように利用するのか**を学びます。

---

## 【準備】APIサービスへの登録

このChapter以降で利用するAPIサービスに事前に登録を行います。どちらも無料で利用できますが、APIキーの取得が必要なためアカウント登録が必要です。

### 1. The Cat API への登録

猫の画像をランダムに取得できるAPIです。

1. [The Cat API](https://thecatapi.com/) にアクセス
2. 「Sign Up」からアカウントを作成
3. 登録したメールアドレスにAPIキーが届く
4. APIキーを控えておく（後の実装で使用します）

### 2. OpenWeatherMap API への登録

天気情報を取得できるAPIです。

1. [OpenWeatherMap](https://openweathermap.org/api) にアクセス
2. 「Sign Up」からアカウントを作成
3. ログイン後、「API keys」タブからAPIキーを確認
4. APIキーを控えておく（後の実装で使用します）

> **注意：** OpenWeatherMap APIのキーは発行後、有効になるまで数時間かかる場合があります。早めに登録しておきましょう。

## Web APIとは

Web APIとは、**インターネット上に公開されている便利なメソッドのようなもの**です。

URLにアクセスすることで、データの取得や登録などの操作を簡単に行うことができます。Reactコースの学習でも `fetch` を利用してURLにアクセスしたことがあるかと思いますが、あれもWeb APIを叩いてデータを取得していたのです。

Web APIは人が作ったものなので、皆さん自身も作ることが可能です。実務ではAPIを「使う」だけでなく「作る」立場になることもあります（Chapter4で体験します）。

---

## フロントエンドとサーバーの連携の仕組み

Webアプリケーションには「リクエスト」と「レスポンス」という仕組みがあります。

```
┌──────────────┐          リクエスト          ┌──────────────┐
│              │  ─────────────────────────→  │              │
│  クライアント  │                              │   サーバー    │
│ （ブラウザ）   │  ←─────────────────────────  │              │
│              │          レスポンス          │              │
└──────────────┘                              └──────────────┘
```

- **リクエスト**：クライアント（ブラウザ）からサーバーに対して「このデータをください」「このデータを登録してください」と要求すること
- **レスポンス**：サーバーからクライアントに対して結果を返すこと

---

## JSON形式のデータ構造

APIでやり取りされるデータは、多くの場合 **JSON（JavaScript Object Notation）** という形式で送受信されます。

```json
{
  "weather": {
    "description": "clear sky",
    "temperature": 25.3
  }
}
```

JSONはJavaScriptのオブジェクトと非常に似た構造をしているため、これまでのReact学習で触れた形式と同様に扱うことができます。

## HTTPメソッド

リクエストには種類があり、**何をするのか**に応じて使い分けます。

| HTTPメソッド | 役割 | CRUDとの対応 |
|---|---|---|
| `GET` | データの取得 | Read |
| `POST` | データの新規登録 | Create |
| `PUT` / `PATCH` | データの更新 | Update |
| `DELETE` | データの削除 | Delete |

この4つの操作を **CRUD（Create / Read / Update / Delete）** と呼びます。Webサービスにおけるデータ操作の基本ですので、しっかり覚えておきましょう。

---

## ステータスコード

レスポンスには **ステータスコード** と呼ばれる数字が含まれており、リクエストの結果を示しています。

| コード | 意味 | 説明 |
|---|---|---|
| `200` | OK | リクエスト成功 |
| `201` | Created | データの作成に成功 |
| `400` | Bad Request | リクエストに問題がある |
| `401` | Unauthorized | 認証が必要（APIキーが無い等） |
| `404` | Not Found | 指定したリソースが見つからない |
| `500` | Internal Server Error | サーバー側のエラー |

ステータスコードを見ることで、**リクエストが成功したのか、失敗したのか、何が原因なのか**を素早く判断できます。

---

## リクエストの構成要素

リクエストは以下の要素で構成されています。

- **URL**：どのリソースに対してリクエストを行うかを示す
- **HTTPメソッド**：どの操作を行うかを示す（GET / POST / PUT / DELETE）
- **Header（ヘッダー）**：APIキーやコンテンツの形式（JSONなど）を指定する
- **Body（ボディ）**：POSTやPUTで送る場合にデータを渡す部分

### GETリクエストの例

```
GET https://api.openweathermap.org/data/2.5/weather?q=Tokyo&appid=YOUR_API_KEY
```

GETでリクエストする場合は、URLの後ろに `?` を付けることでデータを含めた形式にすることが可能です。

`?Key=Value` の形式のURLに含める文字を **クエリパラメータ** と呼びます。複数のパラメータがある場合は `&` で繋ぎます。

### レスポンスの構成要素

- **ステータスコード**：リクエストが成功したか失敗したかを表す
- **Header**：レスポンスのメタ情報
- **Body**：実際のデータ（JSON形式）

## APIドキュメントの読み方

Web APIを利用するには、そのAPIの **ドキュメント（説明書）** を読む必要があります。

ドキュメントから読み取るべき情報は以下の4つです。

1. **エンドポイント（URL）**：どのURLにリクエストを送るか
2. **HTTPメソッド**：GET / POST / PUT / DELETE のどれを使うか
3. **必要なパラメータ**：クエリパラメータやヘッダー情報（APIキーなど）
4. **レスポンス形式**：どんなJSONデータが返ってくるか

### 実際にドキュメントを読んでみよう

OpenWeatherMap APIのドキュメントを開いてみましょう。

**URL：** https://openweathermap.org/current

このページから以下の情報を読み取ってみてください。

- どのURLにリクエストすればよいか
- どんなクエリパラメータが必要か
- レスポンスにはどんなデータが含まれているか

> **ヒント：** `api.openweathermap.org/data/2.5/weather` がエンドポイントであり、`q`（都市名）と `appid`（APIキー）がパラメータとして必要です。

## Chrome DevTools の紹介

ブラウザに備わっている **Chrome DevTools** は、API通信の確認やデバッグに非常に役立つツールです。

### 開き方

- `F12` キーを押す
- または右クリック → 「検証」を選択

### Networkタブ

**Networkタブ**では、ブラウザが行った通信の一覧を確認できます。

- リクエストのURL
- HTTPメソッド
- ステータスコード
- レスポンスの内容（JSON）

次のChapterでReactからAPIを呼び出す際に活用しますので、一度開いて確認しておきましょう。

---

## 本Lessonのまとめ

- Web APIはインターネット上に公開された「便利なメソッド」のようなもの
- クライアントからサーバーへの **リクエスト** と、サーバーからの **レスポンス** でデータをやり取りする
- HTTPメソッド（GET/POST/PUT/DELETE）は **CRUDに対応** している
- ステータスコードでリクエストの成功・失敗を判断する
- APIドキュメントから **URL・メソッド・パラメータ・レスポンス形式** を読み取る
- Chrome DevToolsのNetworkタブでAPI通信を確認できる
