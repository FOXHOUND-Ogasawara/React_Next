# Lesson06：【実践課題】CRUD処理の統合と差分確認

## 課題の概要

Lesson02〜05で個別に実装してきたCRUD処理を、ひとつのアプリケーションとして統合し、全機能が正しく動作することを確認する実践課題です。

---

## 課題1：全機能の統合テスト

### 課題設問

以下の操作を一連の流れで実行し、すべて正常に動作することを確認してください。各操作後に確認すべき内容も記載しています。

1. **一覧表示（Read）** — アプリケーションを起動し、初期データ（3件）が表示されることを確認
2. **新規登録（Create）** — 名前「テスト太郎」、年齢「20」を登録
3. **編集（Update）** — テスト太郎の名前を「テスト次郎」、年齢を「25」に変更
4. **削除（Delete）** — テスト次郎を削除
5. **データベース確認** — pgAdminで `SELECT * FROM sample_users;` を実行

各操作が正常に動作したことを示すため、以下を回答してください。

- 操作2の後、一覧の表示件数は何件ですか？
- 操作4の後、一覧の表示件数は何件ですか？
- 操作5で確認したテスト次郎のレコードの `deleted` カラムの値は何ですか？

### 解答

- 操作2の後、一覧の表示件数は **4件**（初期データ3件 + 新規登録1件）
- 操作4の後、一覧の表示件数は **3件**（テスト次郎が論理削除されたため）
- テスト次郎のレコードの `deleted` カラムの値は **`true`**（物理削除ではなくレコード自体は残っている）

## 課題2：VSCodeのソース管理タブで差分確認

### 課題設問

VSCodeのソース管理タブ（`Ctrl + Shift + G`）を開き、全ての変更ファイルの差分を確認してください。

以下のチェック項目について、それぞれ該当する問題箇所があったかどうかを回答し、あった場合は修正してください。

1. 不要な `console.log` が残っていないか
2. コメントアウトしたテスト用コードが残っていないか
3. APIのURLがハードコーディングされている箇所は何ファイルあるか
4. インデントが崩れている箇所がないか
5. 未使用の `import` 文が残っていないか

### 解答

1. 開発中に入れた `console.log('デバッグ用:', data)` 等は削除する。`console.error` によるエラーログは残してよい。
2. `// const oldFunction = ...` のようなコメントアウト済みの不要コードは削除する。
3. `http://localhost:3001/api/users` がハードコーディングされている箇所を確認する。理想的には定数化して1箇所にまとめるとよい。
   ```tsx
   const API_BASE_URL = 'http://localhost:3001/api';
   ```
4. コードのインデントが2スペースまたは4スペースで統一されていることを確認する。
5. 使わなくなった `import` ステートメントは削除する（例：途中で削除した機能のimport等）。

## 課題3：コミットと整理

### 課題設問

差分確認が完了したら、以下の手順を実行してください。

1. 修正後の状態で `git add .` と `git commit` を実行する
2. コミットメッセージは何をしたかが分かる内容にすること
3. リモートリポジトリにプッシュする

### 解答

```bash
git add .
git commit -m "CRUD処理の実装完了・コード整理済み"
git push origin main
```

> **補足：** まだGitHubリポジトリを作成していない場合は、GitHub上で新規リポジトリを作成し、`git remote add origin URL` で紐づけてからpushしてください。

## 課題4：振り返り

### 課題設問

このChapterで学んだことを以下の表の空欄に埋めて整理してください。

| 操作 | HTTPメソッド | バックエンドのSQL | フロントエンドの処理 |
|---|---|---|---|
| Read | _____ | _____ | _____ |
| Create | _____ | _____ | _____ |
| Update | _____ | _____ | _____ |
| Delete | _____ | _____ | _____ |

### 解答

| 操作 | HTTPメソッド | バックエンドのSQL | フロントエンドの処理 |
|---|---|---|---|
| Read | `GET` | `SELECT` 文でデータ取得 | `useEffect` + `fetch` でデータ表示 |
| Create | `POST` | `INSERT` 文でデータ登録 | フォーム入力 + `fetch` で登録 |
| Update | `PATCH` | `UPDATE` 文でデータ更新 | `useParams` で対象特定 + `fetch` で更新 |
| Delete | `PATCH` | `UPDATE` 文で論理削除 | `confirm` で確認後 `fetch` で削除 |
