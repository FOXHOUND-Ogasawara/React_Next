# Lesson06：【実践課題】CRUD処理の統合と差分確認

## 課題の概要

Lesson02〜05で個別に実装してきたCRUD処理を、ひとつのアプリケーションとして統合し、全機能が正しく動作することを確認する実践課題です。

---

## 課題1：全機能の統合テスト

以下の操作を一連の流れで実行し、すべて正常に動作することを確認してください。

### テスト手順

1. **一覧表示（Read）**
   - アプリケーションを起動し、ユーザー一覧が表示されること

2. **新規登録（Create）**
   - 新しいユーザー（名前：テスト太郎、年齢：20）を登録
   - 一覧にテスト太郎が表示されること

3. **編集（Update）**
   - テスト太郎の名前を「テスト次郎」、年齢を「25」に変更
   - 一覧でテスト次郎（25歳）に変更されていること

4. **削除（Delete）**
   - テスト次郎を削除
   - 一覧からテスト次郎が消えていること

5. **データベースの確認**
   - pgAdminで `SELECT * FROM sample_users;` を実行
   - テスト次郎のレコードが `deleted = true` になっていること

### チェックリスト

- [ ] Read：一覧が正しく表示される
- [ ] Create：新規登録が正常に動作する
- [ ] Update：編集内容が反映される
- [ ] Delete：論理削除が正しく動作する
- [ ] 削除済みデータが一覧に表示されない

---

## 課題2：VSCodeのソース管理タブで差分確認

全機能の実装が完了したら、ソース管理タブで変更差分を確認しましょう。

### 確認手順

1. VSCodeでソース管理タブを開く（`Ctrl + Shift + G`）
2. 変更されたファイルの一覧を確認する
3. 各ファイルをクリックして差分を確認する

### 確認観点

以下の観点でコードを見直してください。

- [ ] 不要な `console.log` が残っていないか
- [ ] コメントアウトしたテスト用コードが残っていないか
- [ ] APIのURLがハードコーディングされている場合、一箇所にまとめられないか
- [ ] インデントが崩れている箇所がないか
- [ ] 未使用の `import` 文が残っていないか

### 差分確認で気づいたことがあれば修正する

差分確認で不要なコードを見つけたら、削除してから再度 `git add` & `git commit` を行いましょう。

---

## 課題3：コミットと整理

差分確認が完了したら、Gitにコミットしましょう。

```bash
git add .
git commit -m "CRUD処理の実装完了"
git push origin main
```

> **リモートリポジトリの設定：** まだGitHubリポジトリを作成していない場合は、GitHub上で新規リポジトリを作成し、`git remote add origin URL` で紐づけてからpushしてください。

## 振り返り

このChapterで学んだことを振り返りましょう。

### 学んだ技術

| 操作 | HTTPメソッド | バックエンドの処理 | フロントエンドの処理 |
|---|---|---|---|
| Read | GET | `SELECT` 文でデータ取得 | `useEffect` + `fetch` でデータ表示 |
| Create | POST | `INSERT` 文でデータ登録 | フォーム入力 + `fetch` で登録 |
| Update | PATCH | `UPDATE` 文でデータ更新 | `useParams` で対象特定 + `fetch` で更新 |
| Delete | PATCH | `UPDATE` 文で論理削除 | `confirm` で確認後 `fetch` で削除 |

### 理解したアーキテクチャ

```
React（フロント） → Node.js/Express API（バック） → PostgreSQL（DB）
```
