# Lesson01：演習プロジェクトの準備とコードリーディング

## はじめに

このChapterでは、**既存のプロジェクトを読み解き、機能を追加する**という実務に近い体験を行います。

実務では0からプロジェクトを作ることは多くありません。既に運用されているプロジェクトに参画し、追加のタスクを行うことがほとんどです。そのためには、**ソースコードを読み、どこで何をしているのかを読み解く能力**が求められます。

---

## 演習プロジェクトの環境構築

### 1. ZIPファイルのダウンロードと展開

配布されたZIPファイル（`dashboard-app.zip`）をダウンロードし、任意のフォルダに展開してください。

### 2. 自分のGitHubリポジトリとして初期化

展開したプロジェクトを自分のGitHubリポジトリとして管理します。

```bash
cd dashboard-app
git init
git add .
git commit -m "初期コミット"
```

GitHubで新規リポジトリを作成し、リモートリポジトリとして登録します。

```bash
git remote add origin https://github.com/あなたのアカウント/dashboard-app.git
git push -u origin main
```

### 3. 依存関係のインストールと動作確認

```bash
npm install
npm run dev
```

ブラウザでアクセスし、ダッシュボード画面が表示されることを確認してください。

---

## コードリーディング

プロジェクトが動作することを確認したら、**ソースコードを読んでプロジェクトの構造を把握**しましょう。

### ディレクトリ構造の確認

```
dashboard-app
└ src
   ├ components       ← UIコンポーネント
   │  ├ Header.tsx
   │  ├ SideMenu.tsx
   │  ├ NotificationCenter.tsx
   │  └ PlaceholderChart.tsx
   ├ data             ← モックデータ
   │  ├ notifications.ts
   │  ├ salesData.ts
   │  └ userData.ts
   ├ pages            ← ページコンポーネント
   │  ├ Dashboard.tsx
   │  ├ Notifications.tsx
   │  └ Settings.tsx
   └ App.tsx           ← ルーティング設定
```

### 読み解くポイント

以下の観点でコードを確認し、プロジェクト全体の構造を把握してください。

#### 1. App.tsx：ルーティングの構造

- どのURLにアクセスすると、どのページが表示されるか？
- サイドメニューとメインコンテンツの関係はどうなっているか？

#### 2. Dashboard.tsx：ダッシュボード画面の構成

- 現在どんなコンポーネントが表示されているか？
- `PlaceholderChart` は何を表しているか？

#### 3. data/ ディレクトリ：利用可能なデータ

- `userData.ts` にはどんなデータが含まれているか？
- `salesData.ts` にはどんなデータが含まれているか？

#### 4. components/ ディレクトリ：既存のUIコンポーネント

- `Header.tsx` はどんな機能を持っているか？
- `SideMenu.tsx` にはどんなメニュー項目があるか？

### コードリーディングのチェックリスト

以下の項目が把握できたか確認してください。

- [ ] プロジェクト全体のフォルダ構成を把握した
- [ ] ルーティングの仕組み（URL → ページの対応）を把握した
- [ ] 利用可能なモックデータの構造を把握した
- [ ] 既存コンポーネントの役割を把握した
- [ ] `PlaceholderChart` を実際のグラフに置き換えるべきだと理解した

## 本Lessonのまとめ

- 実務では **既存プロジェクトのコードリーディング** が重要なスキル
- ZIPからプロジェクトを展開し、自分のGitHubリポジトリとして管理する
- ディレクトリ構造 → ルーティング → データ → コンポーネントの順に把握する
- 次のLessonでは、このプロジェクトにダッシュボード機能を追加する段取りを組みます
