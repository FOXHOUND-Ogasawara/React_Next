# Lesson06：【テキスト】ソース管理タブでの差分確認と実装結果の整理

## はじめに

ダッシュボードの実装が完了したら、**変更内容を確認し、不要なコードを除去**する整理のフェーズに入ります。

このLessonでは、VSCodeのソース管理タブを使った差分確認の具体的な手順と、チェックすべき観点を解説します。

---

## 差分確認の手順

### 1. ソース管理タブを開く

- VSCodeの左サイドバーでソース管理アイコン（分岐のマーク）をクリック
- または `Ctrl + Shift + G` を押す

### 2. 変更ファイルの一覧を確認

変更・追加・削除されたファイルが一覧で表示されます。

- **M**（Modified）：変更されたファイル
- **U**（Untracked）：新規追加されたファイル
- **D**（Deleted）：削除されたファイル

### 3. 各ファイルの差分を確認

ファイルをクリックすると、変更前（赤）と変更後（緑）が並べて表示されます。

---

## チェックすべき観点

### ① 不要な console.log が残っていないか

開発中にデバッグ用に入れた `console.log` は、実装完了後に必ず削除しましょう。

```tsx
// ❌ 残ってはいけない
console.log('デバッグ用:', data);

// ✅ 必要な場合はエラーログのみ残す
console.error('データ取得に失敗しました:', error);
```

### ② コメントアウトしたコードが残っていないか

試行錯誤の過程でコメントアウトしたコードは削除しましょう。

```tsx
// ❌ 不要なコメントアウト
// const oldFunction = () => { ... };

// ✅ 説明のためのコメントは残す
// ステータスコードに応じたエラーハンドリング
```

### ③ 未使用の import 文が残っていないか

使わなくなったインポートは削除します。

### ④ インデントやフォーマットが崩れていないか

コードの読みやすさは品質の一部です。インデントが乱れていたら修正しましょう。

### ⑤ 意図しない変更が含まれていないか

別のファイルを誤って変更していないか確認します。

---

## 実装結果の整理

差分確認が完了し、不要なコードを除去したら、最終的にコミットします。

### コミットメッセージのポイント

```bash
# ❌ 曖昧なメッセージ
git commit -m "修正"

# ✅ 何をしたかが分かるメッセージ
git commit -m "ダッシュボードにグラフコンポーネントを追加"
```

---

## 本Lessonのまとめ

- VSCodeソース管理タブで **変更ファイル一覧 → 差分確認** の手順を学んだ
- 不要コード（console.log・コメントアウト・未使用import）の除去が重要
- 実務ではPR（プルリクエスト）前の自己チェックとして必須の工程
- 次のLessonでは、この整理作業を課題として実践します
