# Lesson03：【課題】ダッシュボード機能の実装計画を作成する

## 課題の概要

Lesson02で学んだタスク分解の方法を参考に、**自分自身でダッシュボード機能の実装計画を作成**してください。

---

## 課題1：実装計画の作成

### 課題設問

以下のフォーマットに従い、ダッシュボードに追加する全機能（7項目）の実装計画を作成してください。

**フォーマット：**

```markdown
【タスク名】
  ・対象ファイル
  ・実装する内容（箇条書き）
  ・使用するデータ / ライブラリ
  ・補足事項
```

**作成すべき項目：**

1. ユーザー統計グラフ（棒グラフ）の作成
2. 売上データグラフ（折れ線グラフ）の作成
3. 商品データ（モックデータ）の作成
4. カテゴリ別割合の円グラフの作成
5. 商品別売上の円グラフの作成
6. ダッシュボード画面の修正
7. 商品一覧ページの追加

### 解答

```markdown
【タスク1】ユーザー統計グラフの作成
  ・対象ファイル：components/UserStatsChart.tsx（新規作成）
  ・実装する内容
    - Recharts の BarChart を使用して棒グラフを表示
    - X軸：月、Y軸：ユーザー数
    - 新規ユーザーとアクティブユーザーの2系列を表示
  ・使用するデータ：data/userData.ts
  ・使用ライブラリ：recharts

【タスク2】売上データグラフの作成
  ・対象ファイル：components/SalesChart.tsx（新規作成）
  ・実装する内容
    - Recharts の LineChart を使用して折れ線グラフを表示
    - 日別/週別/月別の切り替え機能を実装
    - useState で期間を管理、ボタンクリックで表示データを切り替え
  ・使用するデータ：data/salesData.ts（dailySalesData, weeklySalesData, monthlySalesData）
  ・使用ライブラリ：recharts

【タスク3】商品データの作成
  ・対象ファイル：data/productData.ts（新規作成）
  ・実装する内容
    - Product型とCategory型のインターフェースを定義
    - 6種類以上の商品データを追加
    - 6種類以上のカテゴリデータを追加
  ・使用するデータ：なし（新規作成）

【タスク4】カテゴリ別円グラフの作成
  ・対象ファイル：components/CategoryPieChart.tsx（新規作成）
  ・実装する内容
    - Recharts の PieChart を使用して円グラフを表示
    - カテゴリ別の割合を表示
  ・使用するデータ：data/productData.ts（categoryData）
  ・使用ライブラリ：recharts

【タスク5】商品別売上円グラフの作成
  ・対象ファイル：components/SalesPieChart.tsx（新規作成）
  ・実装する内容
    - Recharts の PieChart を使用して円グラフを表示
    - 商品ごとの売上金額を表示
  ・使用するデータ：data/salesData.ts（productSalesData）
  ・使用ライブラリ：recharts

【タスク6】ダッシュボード画面の修正
  ・対象ファイル：pages/Dashboard.tsx（修正）
  ・実装する内容
    - PlaceholderChartを削除
    - 作成した4つのグラフコンポーネントをインポートして配置
    - 2×2のグリッドレイアウトで配置
  ・補足事項：Grid コンポーネントを利用すると整列しやすい

【タスク7】商品一覧ページの追加
  ・対象ファイル
    - pages/Products.tsx（新規作成）
    - App.tsx（ルーティング追加）
    - components/SideMenu.tsx（メニュー項目追加）
  ・実装する内容
    - テーブルで商品情報（ID・商品名・カテゴリ・価格）を表示
    - ルーティング /products を追加
    - サイドメニューに「商品一覧」リンクを追加
  ・使用するデータ：data/productData.ts（products）
```

## 課題2：実装計画の自己レビュー

### 課題設問

作成した実装計画を、Lesson02のタスク分解例と比較し、以下の観点で自己レビューしてください。

1. タスクの分解粒度は適切か？（大きすぎず、小さすぎず）
2. 実装に必要な情報（ファイル名・使用データ等）が含まれているか？
3. 実装の順序に論理的な理由があるか？（依存関係を考慮しているか）

### 解答

1. **粒度**：1タスク = 1コンポーネント or 1ファイルの粒度が適切。「ダッシュボード画面をすべて作る」のように大きすぎるとタスクが漠然とし、「import文を書く」のように小さすぎると管理が煩雑になる。
2. **情報の網羅性**：各タスクに「対象ファイル」「使用データ」「使用ライブラリ」が含まれていれば十分。不明点が残る場合は「確認事項」として明記する。
3. **順序の論理性**：
   - タスク3（商品データ）はタスク4・5・7よりも先に行うべき（データがないとグラフやページが作れない）
   - タスク1〜5（個別コンポーネント）はタスク6（ダッシュボード統合）よりも先に完了している必要がある
   - タスク7（商品一覧ページ）はタスク3の後であれば独立して実装可能
